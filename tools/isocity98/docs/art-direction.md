# 美术方向

这份文档说明「为什么这套管线看起来像 90 年代」的具体机制：色板怎么选、明暗怎么定、阴影方向怎么来、网点怎么替代贴图、CRT 参数各自解决什么问题。

一句话概括：**观感来自约束，不来自细节**。有限色板、固定光源、规则网点、严格对齐的网格，这四件事同时成立时，复古质感就出现了；任何一件放松（比如允许连续渐变色、允许实时随机噪声），画面会立刻变成「低分辨率的现代渲染」。

## 1. 97 色母板

母板定义在 `internal/art/palette.go` 的 `rampDefs`：**21 条色阶，共 97 个颜色**。色相按 DOS/VGA 与 PC-98 时代的共性挑选——低饱和的暖灰 / 砖红 / 土黄 + 冷灰 / 青绿，外加三组 PC-98 标志性的高饱和青 / 品红点缀。

每条色阶都由暗到亮排列（`newPalette` 里按 `luma = 0.299R + 0.587G + 0.114B` 排序，保证 `Snap(ramp, pos)` 是单调的）。精灵图、地形、UI、CRT 渐变**共用这一份母板**，这是「整屏和谐」的根源。

母板里有三条**跨色阶复用**的语义：

- `neon/0 = #ffffff` 是画面中唯一的纯白，只用于自发光核心与 UI 高光。
- `ink/0 = #0a0a0e` 被烘焙阴影硬编码引用（`drawShadow`），而不是走材质表——阴影是全局一致的一层，不该各自为政。
- `water/*` 同时被用作玻璃材质的色阶（`wall.glass`）与夜间「熄灯窗户」的 `OffRamp`。玻璃与熄灯的窗本来就是同一件事：反射天光的冷色面。

调色板以 `palette.json` 形式导出，运行时 `web/js/palette.js` 是它的同构实现（同样的色阶列表、同样的 `Snap`/`LerpRamp` 语义、同样的加权最近色 LUT）。UI 从这份表里取名色：

```js
face: c('grey', 0.30),  faceDark: c('grey', 0.10), light: c('grey', 0.90),
mid: c('grey', 0.52),   ink: c('ink', 0.20),       accent: c('teal', 0.55),
warn: c('roof', 0.60),  gold: c('gold', 0.70),     sel: c('teal', 0.85),
```

也就是说 UI 与场景**不可能**跑出色板之外——没有第二份颜色定义。

## 2. 三色调明暗约定与色阶位置

材质表里的每个材质都写成 `mat(name, ramp, pattern, top, left, right)`，三个数字是该朝向在**色阶上的位置**（0..1），不是亮度倍数。四个朝向槽位是：

| 槽位 | 常量 | 对应面 | 屏幕方向 | 典型位置 |
| --- | --- | --- | --- | --- |
| 0 | `art.ShadeTop` | `FaceTop` / `FaceBottom` | 顶面（水平） | 0.85 ~ 0.95 |
| 1 | `art.ShadeLeft` | `FacePosY`、`FaceNegX` | 朝屏幕左下 | 0.44 ~ 0.56 |
| 2 | `art.ShadeRight` | `FacePosX`、`FaceNegY` | 朝屏幕右下 | 0.16 ~ 0.26 |
| 3 | `art.ShadeBottom` | 底面 | 正常不可见 | 固定 0.12 |

**为什么是 `0.9 / 0.5 / 0.2` 这三个数。** 母板色阶大多只有 5 档；`Snap(ramp, pos)` 是硬边取档（`round(pos*(n-1))`）。把三个位置取在 0.9 / 0.5 / 0.2，在 5 档色阶上分别落在**第 4、2、0 档**——也就是最小、中间、最大三档里彼此分离的三档，中间还各空一档。若把手调位置挤在相邻档位（比如 0.6 / 0.5 / 0.4），立方体的三个面会落到同色或近似色，「体积感」立刻消失，看起来像一块平贴图。6 档色阶（`grey`/`stone`/`grass`/`water`）上就是第 5、3、1 档，同样保持分离。

具体到几类材质：

| 材质 | 色阶 | top / left / right | 意图 |
| --- | --- | --- | --- |
| `wall.concrete` | grey | 0.92 / 0.50 / 0.20 | 中性混凝土，三面拉满对比 |
| `wall.brick` | brick | 0.82 / 0.48 / 0.20 | 砖墙略压暗，留出线脚提亮空间 |
| `wall.brick.dark` | brick | 0.58 / 0.34 / 0.14 | 整体压暗的深色砖（联排副单元） |
| `wall.glass` | water | 0.74 / 0.44 / 0.18 | 玻璃不靠亮度，靠 `glass` 图案的横向条纹 |
| `roof.slate` | steel | 0.44 / 0.26 / 0.10 | 深色屋面主动压暗（否则高处一片惨白） |
| `window` | sky | 0.30 / 0.16 / 0.02 | 窗**故意比墙暗**：白天玻璃反射天光但更暗，读作「洞」而不是「亮块」 |
| `trim.white` | grey | 0.96 / 0.62 / 0.30 | 线脚永远是最亮的，勾出建筑轮廓 |
| `water` | water | 0.72 / 0.44 / 0.20 | 水面 |
| `car.white` | grey | 0.96 / 0.60 / 0.28 | 车辆用高对比，好在小尺寸下辨认 |

注意 `window` 的位置（0.30 / 0.16 / 0.02）**低于**同墙的取值。这是有意的：如果窗户比墙亮，一栋楼会变成满墙亮点；让窗比墙暗，窗户才读作「开口」。夜间则由自发光材质整体替换（见下），白天黑夜的窗户是两套完全不同的材质。

**夜间档怎么改这三档。** `Profile` 不做逐材质替换，只做两件全局的事：

| Profile | ShadeScale | Tint | TintAmt | ShadowA | GlowGain |
| --- | --- | --- | --- | --- | --- |
| `Day` | 1.0 | 无 | 0 | 0.30 | 0.0 |
| `Night` | 0.58 | `#3b4059`（`shadow/1`） | 0.34 | 0.20 | 1.0 |

即：所有明暗位置乘 0.58（整体压暗），再向 `#3b4059` 混合 34%（偏冷蓝，模仿月光/钠灯的色偏），阴影更淡（夜里阴影不该那么硬）。然后夜间档把 `window` / `window.small` / `door.glass` / `window.hall` 换成自发光材质（`Ramp: gold`，息灯时用 `OffRamp: water`），把 `sign.neon.*` 换成 `neon` 图案版本（`Glow 1.4`），并把 `streetlamp` 换成自发光版本（`Glow 1.6`）。自发光像素额外进 `lit` 层，经模糊后加法叠回——这就是夜间窗户的辉光。

## 3. 投影方向与「为什么阴影方向是美术指定」

光源约定是**左上**（等距世界里即 `-X, -Y` 方向的斜上方），因此：

- 阴影方向是**屏幕右下**，与光源一致；
- 朝屏幕左下（+Y）的面是受光侧（`ShadeLeft`，较亮）；
- 朝屏幕右下（+X）的面是背光侧（`ShadeRight`，最暗）；
- 边缘处理的 `Rim` 只在上 / 左上 / 左三个方向提亮——那是受光轮廓。

阴影的实现是**扫掠体**（`ShadowSrc`：底面矩形 + `z0..z1`），沿光方向按高度平移 7 步、每步画一个底面矩形并取并集，颜色固定 `#0a0a0e`：

| 参数 | 日间 | 夜间 |
| --- | --- | --- |
| `DX` | 0.36 格 / 单位高度 | 同 |
| `DY` | 0.155 格 / 单位高度 | 同 |
| `Alpha` | 0.30 | 0.20 |
| `Steps` | 7 | 7 |

（`DX/DY` 与 `Alpha` 写在 `cmd/prerender/main.go` 的 `optionsFor` 里，不是硬编码在渲染器。）

**为什么不用物理正确的投影。** 物理正确的阴影需要光源方向、可见性、软阴影半径、以及正确的透视投影——而这里用的是**正交投影**，物理上根本就不存在「因为离光源更远所以更长」的透视缩短。更要紧的是观感取舍：

1. **可读性优先**。等距建造游戏里阴影的主要功能是「让建筑从地面浮起来」和「标出占地范围」，不是表现光照。方向一致、长度统一（只由 `Height` 决定）的阴影，让人一眼读出建筑的高度层级（`h3d` 从 1.6 到 11.5 差 7 倍，阴影长度也差 7 倍）。
2. **方向固定才能烘焙**。方向一旦固定，阴影就可以在离线阶段和精灵图一起烘死，运行时零成本；若要在运行时算方向，就必须保存场景几何，也就失去了这套架构的全部好处。
3. **`DY < DX` 是等距的必然**。屏幕 Y 方向被压缩了一半（32x16 的菱形），所以要让阴影在屏幕上看起来是「右下 45°」，世界坐标里 `DX` 就必须约等于 `2*DY`。取 `0.36 / 0.155` 比严格 2:1 略偏横，视觉上阴影更贴地。
4. **手调痕迹是风格的一部分**。美术可以给特定建筑改 `Height` 而完全不动物理参数——阴影长一点或短一点，观感立刻不同。`NoShadow` 开关则用于地形/道路/树木（树木的阴影会在地图上炸成一片斑点，反而更乱）。

阴影是**烘焙在精灵图内部**的：它画在物体之下、但仍在同一张图画布里，因此阴影会正确压过地形，也会被更靠南的单体覆盖（画家算法保证）。

## 4. 抖动网点如何替代贴图

整套管线**没有任何位图贴图**。所有「材质」都是 `Pattern` 函数，在面内参数 `(u, v)`（单位：纹素，1 格 = 32 纹素）上采样一个 4x4 有序矩阵，返回 `[-1, 1]` 的明暗偏移，乘 `PatternAmp = 0.15` 后加到色阶位置上。

**为什么是 0.15。** 5 档色阶上相邻两档的间距是 0.25；`Snap` 是硬边取档。偏移取 ±0.15（总幅度 0.3 > 0.25）意味着**网点确实会在相邻两档之间跳**——一半像素取亮档、一半取暗档，形成经典的「双色抖动」材质。若把幅度压到 0.1 以下，网点会全部落回同一档，图案消失；若放大到 0.5 以上，网点会跨越两三档，材质会变脏、并且丢失底色。所以这个常数是「刚好能跳一档」的临界值。

**为什么 `cell` 用 2 而不是 1。** `ord(cell, u, v)` 把 `cell x cell` 个纹素合并成一个网点块。`cell = 1` 是逐像素噪点，在 1x 分辨率下看起来是「沙沙的噪声」；`cell = 2` 得到 2x2 像素的规则块，正是 DOS 时代 VGA 素材的观感。多数图案用 2，墙面用 3~4（大块抹灰/石墙），只有 `plank` 的底层噪波用 1。

**图案的三层结构。** 每个图案基本是「结构线 + 网点」的叠加，结构线用固定的负值（压暗）表达缝隙：

| 结构 | 表达方式 | 出现在 |
| --- | --- | --- |
| 砖缝 / 石缝 | 固定负值（`brick` 用 -0.9/-0.7，`stonewall` 用 -0.9/-0.7） | 砖墙、石墙、岩壁 |
| 横向壁板 | 每 3 纹素一道 -0.8 | `siding` |
| 楼层横梁 | 每 4 纹素一道 -0.7（楼板）+ -0.35（窗框） | `glass` |
| 屋面板缝 | 每 2 纹素一道 -0.55 | `roofing` |
| 混凝土浇注缝 | 每 8 纹素一道 -0.85 | `concrete` |
| 木纹 | 每 3 纹素一道 -0.45（竖缝） | `plank` |
| 瓷砖 | 4x4 格缝 -0.7 | `tile` |
| 拉丝金属 | 每 5 纹素 +0.45 / -0.45 | `metal` |
| 草地层次 | 2x2 网点 ×0.7 + 8x8 大网点 ×0.55 叠加 | `turf` |
| 水面波纹 | 每 4 纹素 +0.75 / -0.35 + 16x8 周期波峰 | `water` |

**为什么网点比贴图好。** 三个理由：

1. **尺度正确**。位图贴图在等距视角下需要按面朝向做仿射校正，否则会错切；`FaceUV` 直接给出每个面的无错切参数化（顶面用 `(x,y)`，竖面用 `(轴向, -z)`），图案天然不受投影影响。
2. **天然落在有限色板内**。图案输出的是**色阶位置偏移**，最终仍由 `Snap(ramp, pos)` 取色板颜色——图案永远不可能产生色板外的颜色。位图贴图则需要额外量化一遍。
3. **可参数化**。`UOff` / `VOff` 让同一张瓦片换相位即成为「另一个变体」（地形变体就是这么做的：`UOff = frame*5, VOff = frame*3`），水面动画也只是每帧改 `UOff`（`terrain.water` 的 4 帧分别为 `frame*4`）。零额外资产。

## 5. CRT 后处理参数与取舍

CRT 是整屏的最后一站（`web/js/crt.js`）：此时所有精灵图与 UI 都已经画进 640x400 的帧缓冲。处理顺序是**辉光 → 扫描线 → 荫罩 → 暗角 → 有限色板量化**，最后整数倍最近邻放大。

三档模式（`crt.mode`，默认 2）：

| mode | 效果 |
| --- | --- |
| 0 | 关：直接 blit（仍然最近邻放大） |
| 1 | 廉价：blit + 一张 4x2 的扫描线图案平铺覆盖（一次 `drawImage`，不逐像素） |
| 2 | 全效果：逐像素做辉光 + 扫描线 + 荫罩 + 暗角 + 量化 |

| 参数 | 值 | 取舍 |
| --- | --- | --- |
| `scan` | 0.82 | 奇数行亮度乘 0.82（即每两行压暗一行 18%）。再低会明显变暗且闪烁感增强；再高就看不出扫描线 |
| `glow` | 0.55 | 低分辨率辉光的叠加强度（`buildBloom` 的亮度阈值 168、斜率 1/87、先乘 0.5 再两次盒式模糊，模糊在 1/4 分辨率的 160x100 上做，成本可忽略） |
| `vig` | 0.15 | 暗角：边缘乘 `1 - 0.15t²`（`t ∈ [-1,1]`）。二次曲线让中心基本不受影响、只有四角明显压暗 |
| 荫罩 | 0.93 | 每 3 列压暗一列（模拟 RGB 栅条）。只压 7%，因为 CRT 的荫罩在低分辨率下很容易变成「竖条纹」而不是质感 |
| 档位 | OFF / SCANLINE / FULL CRT | SCANLINE 纯 canvas 合成（blit + 扫描线图案 + 暗角径向渐变，约 1.6 ms）；FULL CRT 走逐像素循环（含有限色板量化）。像素密度 ≥3x 时默认 SCANLINE（全效果在 1920x1200 上约 21 ms），按 `C` 可切换 |
| 量化幅度 | 11 | 抖动阈值 `bayer(x,y)`，乘 11 后加进颜色再 `>>2` 查 6-6-6 色表 |

**几个必须一起考虑的取舍：**

- **扫描线在量化之前**。如果先量化再压暗扫描线，被压暗的行会落回色板里的**另一档**（比如整片墙从 `grey/3` 掉到 `grey/2`），屏幕上会出现横条纹而不是扫描线质感。先压暗再量化，被压暗的像素大多会量化回同一档，扫描线表现为「轻微的整体明暗节奏」。
- **抖动幅度取 11，不是 7**。这个幅度比离线渲染的平涂幅度（7）略大：CRT 阶段面对的是**混色后**的像素（UI 抗锯齿、半透明面板），需要一点网点来过渡，否则会出现硬色带。但它又远小于渐变用的 46——大了整屏会变成噪点。
- **先加抖动再夹取**。`clamp255(r + thr*11) >> 2` 的顺序不能反：若先截断再加抖动，255 附近的像素会溢出索引（`>>2` 得 63，加抖动可能到 64），查表越界。
- **整数倍最近邻放大**。放大倍率 `k = max(1, floor(min(winW/640, winH/400)))`，永远整数倍、永远 `imageSmoothingEnabled = false`。若允许非整数倍缩放，1x 的点阵字体和 2x2 网点会被重采样成灰糊，前面所有「像素级」的坚持全部作废。
- **UI 也在 CRT 之下**。UI 与场景共用同一条出口，所以「UI 与场景是同一套东西」在观感上成立——否则一个清晰的现代 UI 压在颗粒感的场景上，会立刻暴露两层。

配合 CRT 的还有字体策略（`web/js/font.js`）：系统字体先渲染到离屏画布，再按 alpha 阈值 0.42 二值化成点阵，然后按色板颜色逐字缓存。直接 `fillText` 会带抗锯齿灰边，破坏「整屏有限色板」——二值化后每个字只有亮/灭两态（12px 高度，PC-98 常见的 12/16 点阵）。

## 6. 观感上最容易踩的几处

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 立方体看起来是平的 | 三个明暗位置挤在相邻档位 | 取 0.9 / 0.5 / 0.2，保证在 5~6 档色阶上分离 |
| 屋顶一半是墙色 | 屋面与墙顶共面，深度相同 | `SlabTop` 固定 `Bias: 0.05` |
| 瓦片拼接缝里透底色 | 菱形边严格重合，光栅化取整归属模糊 | 地形瓦片 `Expand = 0.6` 外扩 + `BinaryAlpha` |
| 渐变天空有硬边横带 | 平涂抖动幅度（7）不足以跨档过渡 | 渐变用 `QuantizeAmp(..., 46)` |
| 窗户变成满墙亮点 | 窗材质比墙亮 | `window` 位置压到 0.30 / 0.16 / 0.02 |
| 夜间辉光被裁掉 | 画布范围按几何体算，不含光晕 | 建筑类 `Pad = 3`（瓦片保持 1） |
| 昼夜切换后贴图整体错位 | 两档裁剪结果差一像素 | 夜间档复用日间画布 + 逐张断言 |
| 缩放后画面糊成灰 | 非整数倍缩放重采样 | 只允许整数倍放大，`imageSmoothingEnabled = false` |
