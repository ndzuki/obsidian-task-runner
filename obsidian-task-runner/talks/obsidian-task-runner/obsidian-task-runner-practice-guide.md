# 演讲练习指南

> 演讲能力不是天生的——是练出来的。这份指南帮你用最少的练习时间，达到"不翻车"的水平。


## 一、练习前：准备工作

### 1. 打印"救命纸条"

把演讲稿里每个 Slide 的**第一句话和最后一句话**抄在一张卡片上：

```
S2:  "周五下午五点钟……" → "剩下的 60% 呢？"
S4:  "左边你在 Obsidian 写需求……" → "就这两个动作。"
S6:  "这两个菱形，我们叫 Gate" → "不会累、不会漏、每步都留记录。"
S22: "说实话。" → "工具会变，原则不会变。"
```

**为什么只抄首尾**：中间的内容你按自己的话讲更自然。但开头和结尾——是每个段落的锚点。错了听众能感觉到。

### 2. 标记你的"安全词"

演讲稿里有些位置标注了【停顿】。在这些位置——用红笔在卡片上画一个 `●`。

```
S2:  ● 周五下午五点钟。● 停顿 2 秒。● 那剩下的 60% 呢？
S6:  ● 区别是什么？● 不会累、不会漏……
S22: ● 说实话。● ●（两个停顿）● 工具会变，原则不会变。
```

**为什么要标记停顿**：紧张时人说话会变快。有显式标记，你会被迫慢下来。

### 3. 准备好 Demo 的退路

```
Plan A: 现场完整演示（网络好、API 正常）
Plan B: 现场写需求 + 播放预录制的 Round 1/2 结果
Plan C: 全程播放录制 + 你解说（网络挂了）
```

在演讲前一天——**必须跑通 Plan C**。录好一个 2 分钟的 screencast，存到桌面。即使一切顺利，Plan C 也可以作为 Q&A 时的"回顾"素材。

录制 Demo 时必须包含一个 5 秒的“重复触发”镜头：Grilling tab 已打开后，再保存一次 TASK 或触发 watcher，画面保持只有一个同任务 tab。这个镜头同时证明系统不是简单地“每次事件都弹通知”。如果现场不方便重复触发，Plan B/C 里保留这段预录片段。

## 二、练习方法

### 不要做的事

- ❌ 对着镜子念稿——你会关注自己的表情而不是内容
- ❌ 在心里默念——大脑觉得"我会了"，嘴巴还不会
- ❌ 一遍遍完整过——时间不够，而且每次都从头开始，后半段永远练得少

### 要做的四轮练习

**第一轮：分段读（30 分钟）**

把演讲按 Slide 分段。每段做三步：

```
1. 读一遍演讲稿上那句话
2. 抬头，对着空气讲一遍（不看稿）
3. 讲不出来？回到第 1 步
```

不需要完整串起来。这一轮的目标是——**每个 Slide 你都能不看看稿讲出核心信息**。

重点练这三个 Slide——它们是你演讲的"命门"：
- **Slide 6（三个 Gate）**：如果只练一张，练这张。这是整场演讲最关键的信息。
- **Slide 13（Demo）**：练到能一边说话一边操作。操作卡住了比忘词更尴尬。
- **Slide 13（单任务去重镜头）**：练习一句话解释两层防重——“owner 防止两个人同时问，tab 去重防止同一入口开两次”。不要说成“全局只能一个 Grilling”，不同任务可以各自打开。
- **Slide 22（三个原则）**：最后一个信息点，听众记住的往往就是这个。

**第二轮：分段计时（20 分钟）**

用手机秒表。每段讲一遍，记录实际用时。

```
Slide 2:    目标 1:30  实际 ___:___
Slide 3-4-5: 目标 5:00  实际 ___:___
Slide 6-7:  目标 3:00  实际 ___:___
Slide 8:    目标 2:00  实际 ___:___
Slide 10-11: 目标 2:00  实际 ___:___
Slide 13:   目标 5:00  实际 ___:___
Slide 14:   目标 2:00  实际 ___:___
Slide 17-18: 目标 1:00  实际 ___:___
Slide 22:   目标 2:30  实际 ___:___
Slide 23:   目标 1:00  实际 ___:___
```

**如果超时了**：不要砍内容——砍过渡句。比如 Slide 4 到 5 的"好，看下一个"可以删掉，直接翻页。

**如果提前了**：不要在中间加速讲新内容——把省下的时间留给 Q&A。

**第三轮：完整串讲（20 分钟 × 2 次）**

完整讲两遍。中间隔至少 2 小时（最好隔夜）。

第一遍——允许自己看稿。重点是感受"一口气讲完 20 分钟"是什么体验。

第二遍——尽量不看稿。翻页时瞥一眼"救命纸条"上的首尾句。中间卡住了？跳到下一张 Slide。不要停下来回想——听众感受不到你跳了一张，但一定能感受到你卡了 10 秒。

**第四轮：模拟实战（如果有条件）**

找一个同事当听众，给他三个问题让他故意在 Q&A 环节问：

```
1. "AI 写的代码质量能信吗？"
2. "这和 Cursor 有什么区别？"
3. "安全吗？数据会泄露吗？"
```

提前准备好答案（演讲指南 Section 六有）。这三个问题大概率会被问到——提前练过回答，Q&A 就不会慌。

## 三、演讲当天的 5 个技巧

### 1. 开场前 30 秒

走到讲台前——站定——扫视全场——微笑——深呼吸一次——然后开口。

**不要做的事**：一边走一边说、一边调麦克风一边说、一边翻第一页一边说。听众的第一个印象是你站定的那一刻——让他看到你是稳的。

### 2. 手势：只用两种

- **指向屏幕**：讲 Gate、流程图、Demo 时，用手指向对应的位置。这是唯一必要的手势。
- **手放下**：其他时间——双手自然垂在身体两侧，或轻轻搭在讲台边缘。

不要插兜、不要抱胸、不要玩笔、不要来回踱步。

### 3. 说太快了怎么办

这是紧张时最常见的反应。给你一个物理锚点——

在演讲稿 Slide 6（三个 Gate）的第一句话前，用红笔写一个 `↓`。看到这个符号——你刻意放慢语速，比你觉得正常的速度慢 30%。

听众不会觉得慢——紧张时你感觉的"正常速度"，听众听起来是"快进"。

### 4. 翻页时机

翻页的黄金瞬间不是你说完最后一句话之后——是**你说到最后一句话的最后一个词时**。

```
❌ "……AI 是执行者，你是决策者。" → 停顿 → 翻页 → 下一页标题出现
✅ "……AI 是执行者，你是——" → 翻页 → "——决策者。" → 下一页已经在屏幕上
```

这样翻页不会打断演讲节奏。练两遍就能掌握。

### 5. 如果 Demo 翻车了

```
1. 不要慌张。观众不知道你预期的是什么。
2. 不要道歉超过一次。"稍等，网络有点慢"——说一遍就够了。
3. 10 秒没恢复 → 切到 Plan B 或 Plan C。
4. 切之前说一句："我们来直接看提前录好的结果。"
```

**没有人因为你的 Demo 出技术问题而否定你的演讲。他们因为你的反应而判断你。**

## 四、演讲不是表演

最后讲一个心态。

你上 TED 看演讲——那些演讲者看起来行云流水。那是因为他们录了 50 遍。你是内部推广——不是 TED。

内部演讲的目标不是"讲得漂亮"。是**"讲得真诚"**。

所以你不需要：
- 不需要背得一字不差——讲错一个词，改过来就行
- 不需要假装激情——你对这个工具的真实感受是什么，就说是什么
- 不需要回答所有问题——"这个问题很好，我需要确认一下再回复你"是一个完全正确的回答

你需要的是：
- 让听众感受到——你用过这个工具，你知道它的好处，也知道它的局限
- 让听众带走一个他们明天就能用的东西——哪怕不是 OTR 本身，是一个原则

把"我要讲好"的包袱放下。你是在分享一个你相信的东西——不是在考试。
